Sección 1 — Arquitectura del flujo de subida

Presigned upload: el binario nunca toca el backend

1
Usuario hace click en el avatar → crop modal
Frontend abre diálogo con ngx-image-cropper. Usuario encuadra la foto y confirma.
Frontend → Backend
2
POST /employees/{key}/photo/upload-url
Backend genera presigned PUT URL (MinIO SDK) + object key. Devuelve { uploadUrl, objectKey }. No toca la BD todavía.
Frontend → MinIO (directo, sin pasar por backend)
3
PUT {uploadUrl} — blob del canvas recortado
Angular hace un PUT HTTP directo a la URL firmada de MinIO. El binario nunca pasa por el backend Java.
Frontend → Backend
4
PUT /employees/{key}/photo — confirma objectKey
Backend construye la URL pública, la persiste en employee.photo_url, actualiza EmployeeResponse. El avatar cambia en la UI.
Flujo de eliminación
DELETE /employees/{key}/photo → backend borra objeto en MinIO + pone photo_url = null → avatar vuelve a iniciales.
Infraestructura: MinIO como nuevo servicio Docker junto a PostgreSQL. Bucket b4rrhh-employee-photos con lectura pública. CORS configurado para localhost:4200.
